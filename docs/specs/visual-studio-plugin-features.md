# Visual Studio 插件功能清单

目标：为 **Visual Studio（非 VS Code）** 开发 Pi x IDE 集成，复现现有 VS Code 插件的用户可见功能。以下是行为要求，不要求复用 VS Code 的扩展 API；通信字段以 [IDE 协议](ide-protocol.md) 为准。

## 1. 打开 Pi 终端与分组

- 提供 **Open Pi in Terminal** 入口，在 IDE 内创建终端并启动 `pi`。
- 插件打开的 Pi 终端尽量集中在右侧独立分组，文件标签尽量保持在左侧；连续打开 Pi 时复用已有终端分组。
- 可以选择使用 tmux 启动 Pi；默认直接启动。
- 不移动用户手动启动的 Pi 终端，也不承诺锁定 IDE 的分组位置。

## 2. 发送文件、文件夹和代码选区

- 在代码编辑器、文件标签和项目资源树的右键菜单提供 **Send to Pi**；编辑器命令可绑定快捷键。
- 有选区时发送 `@相对路径#L起始行-L结束行`；没有选区时发送 `@相对路径`。文件和文件夹发送 `@相对路径`。引用后留一个空格，便于继续输入。
- 发送的是路径引用，不是将整个文件或目录内容复制进 Pi 输入框。
- 成功发送后聚焦目标 Pi 终端，使用户可以直接输入后续内容。

## 3. 精确路由与项目隔离

- 仅发送给当前选中的、**唯一可确认**的 Pi 会话，不向所有连接广播。插件启动的终端使用会话标识关联；手动启动的 Pi 终端只有在终端进程与 Pi 会话能够精确关联时才支持发送。
- 文件、目录和代码选区必须属于目标 Pi 会话所在项目；跨项目、未连接、无法确定目标或关联不唯一时拒绝发送并提示用户。
- 切换文件或选区时，将实时上下文仅同步给同项目的 Pi 会话；其他项目的会话不能收到该项目的内容，已有的过期选区上下文要清除。

## 4. 实时上下文与诊断

- 同步当前文件及选区变化，使 Pi 能获知编辑器的活动上下文。
- 对错误和警告提供 **Pi: Fix it**、**Pi: Send diagnostic** 操作；发送诊断位置、消息与必要的附近代码上下文到当前选中的同项目 Pi 会话。
- 诊断发送成功后聚焦目标 Pi 终端；目标不匹配时提示，不发送给其他会话。

## 验收场景

1. 同一项目有两个 Pi 终端：选中其中一个后右键发送，只有该终端的输入框出现引用并获得焦点。
2. A、B 两个项目各有 Pi 终端：A 的文件和选区不能发给 B；切到 B 时，A 的实时上下文不能残留在 B。
3. 只有 Pi 终端分组时打开第一份文件：文件分组应在终端左侧；后续文件仍进入文件分组。IDE 若不支持相同分组操作，需说明限制。
4. 对错误或警告执行两种诊断操作：只有当前选中的、同项目 Pi 会话收到诊断。
5. 手动启动的 Pi 终端无法唯一关联会话时，发送被拒绝，而不是退化为广播。
